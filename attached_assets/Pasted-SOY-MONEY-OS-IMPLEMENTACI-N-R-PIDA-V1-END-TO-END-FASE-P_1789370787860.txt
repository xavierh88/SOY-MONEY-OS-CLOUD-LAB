==================================================
MÓDULO 1 — PROJECT EXECUTION / BUILD
==================================================

Implementar la capacidad de iniciar un proyecto que ya fue aprobado.

Debe aceptar únicamente proyectos válidos que puedan continuar.

Ejemplo:

projectId = 4
opportunityId = 7
status = PLANNED

Crear el endpoint necesario siguiendo la arquitectura actual.

Preferencia conceptual:

POST /api/projects/:id/start

pero antes verifica si ya existe una ruta equivalente.

NO crear duplicados si ya existe.

Al iniciar:

PLANNED
→ BUILDING

Debe crearse/persistirse una ejecución de proyecto.

La ejecución debe contener como mínimo:

projectId
opportunityId
status
startedAt
currentStage
deliverableType
deliverable
buildNotes

Para esta V1 NO es necesario construir automáticamente software complejo.

El BUILD puede generar un MVP estructurado basado en la oportunidad.

Ejemplos posibles:

DIGITAL_PRODUCT
SERVICE
LANDING_PAGE
REPORT
AUTOMATION
CONSULTING_OFFER
CONTENT_PRODUCT
OTHER

El entregable mínimo debe contener:

title
type
problem
targetCustomer
solution
valueProposition
deliverables
implementationPlan
proposedPrice
assumptions
limitations

No inventar hechos de mercado.

Los datos provenientes de SEARCH_EVIDENCE siguen siendo:

SEARCH_EVIDENCE
NOT_VERIFIED

El BUILD puede utilizarlos como señales, pero NO convertirlos automáticamente en hechos verificados.

==================================================
MÓDULO 2 — QA
==================================================

Después de BUILD debe existir una etapa de revisión.

BUILDING
→ QA_REVIEW

QA debe evaluar como mínimo:

completitud
coherencia
relación con la oportunidad
relación con la evidencia
claridad de la propuesta
viabilidad básica
campos faltantes
contradicciones

Resultado:

PASS

o

NEEDS_FIX

Persistir:

qaStatus
qaScore
issues[]
recommendations[]
checkedAt

Si NEEDS_FIX:

NO marcar el proyecto como terminado.

Debe quedar preparado para una corrección posterior.

Para V1 no necesitamos un loop infinito automático.

Máximo comportamiento seguro:

BUILD
→ QA
→ NEEDS_FIX

o:

BUILD
→ QA
→ PASS

==================================================

Usar las estructuras /api/results y /api/learning existentes si corresponde.

Ejemplo conceptual:
